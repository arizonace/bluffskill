# UI design

## Client

The client is a desktop Qt Widgets application with a landscape table. It launches into a calm, non-interactive empty state: the table has ten seat positions, while server, competition, table, and action controls remain disabled until a connection makes them meaningful.

```text
Connection menu → Connect dialog → server field enabled
                                  ↓
                          competition list enabled
                                  ↓
                             table list enabled
                                  ↓
               player joins → action panel enabled on that player’s turn
```

The ten seats use a fixed semantic layout: three north, two east, three south, and two west, with each player circle centered directly on a straight table border. Every circle has horizontal text in the same top-to-bottom order: player name, larger semi-bold chip count, then folded-hands marker at the circle bottom. A player’s front is cardinal and inward (south for north seats, west for east, north for south, and east for west); no player or element angles toward the table center. The reserved button area abuts the circle at that front; dealer-plus-blind buttons run left-to-right at north/south seats and top-to-bottom at east/west seats. A player’s current-round wager remains just beyond that button area until the betting round closes; only then is it reflected in the center pot. Cards follow in the same inward direction at showdown, always in a left-to-right row; a hand-category description has a visible vertical margin below the cards except at south seats, where it appears above. During live play the local player's compact hole cards occupy the lower-right control area, preserving the local seat’s wager lane; at showdown, their cards and description return to the seat with the other revealed hands. The latest action is in a white box directly counter-clockwise from the circle and the yellow two-line winnings box directly clockwise; both straddle the table border. These boxes show only completed actions; a gold double ring identifies the player expected to act. A busted player's seat is dark gray. The taller table canvas has a 960 x 880 minimum so its full button, card, description, action, and winnings areas do not overlap. The center presents the pot, side pots, current betting-round wager, and community cards, without a betting-street label. Community and local hole cards render as compact rank-and-suit card faces. At a completed hand, each winner has a yellow two-line result box: total chips awarded from the pot and net hand result. The client does not reconstruct per-pot allocation or draw chip stacks. A new game creates a random mix of Leo and Virgo reference players around a human placed uniformly in one of the ten seats; with nine reference seats, it always includes at least one of each type. `Game → Custom Game…` instead accepts exactly ten seats: zero or one local human player plus a count control for every reference-player type advertised by the connected server, currently Leo, August Leo, Virgo, August Virgo, and Libra, plus a Repetitions field from 1 through 28. When present, the human is placed uniformly among the ten seats. When absent, the client plays the selected number of fully automated games, restarting after each winner through the server's color-named game sequence; every player/dealer presentation, including the next hand, uses the Automated Player Delay. `Game → Quit Game` confirms before ending the table and returning the client to its no-local-player state. The table starts after its tenth seat is filled. The requesting player sees their own ranking description even after folding or a non-showdown hand. The clickable dealer button starts the next hand immediately; otherwise the client requests it after the configured deal clock (20 seconds by default), or after the uninterrupted dealer delay when the local player has been eliminated.

The top status area presents server, competition, and table selectors with a compact speaker toggle immediately left of the Pause/Play control. Its speaker and muted-speaker states turn sound effects on and off and persist as the `Sound Effects` preference. The Table Status Line uses fixed-width, read-only fields for remaining players, current small/big blinds, rounds played, and the whole-second next-deal countdown, followed by a Deal Now button enabled only during that countdown. When the human player can act, the action panel shows only a fixed-width `Action Clock` field. On expiry, the client submits Check if still legal, otherwise Fold; the server continues to validate the command. The wager composer sits below the action buttons: it accepts an editable additional wager, displays the resulting total commitment for the current betting round, and has increment/decrement controls for each active server-provided chip denomination plus the dynamically supplied big-blind, minimum-bet, and stack amounts. It does not read denominations from client configuration. When editing completes, an entered wager rounds up to the next multiple of the smallest active denomination without exceeding the player's legal maximum; text remains untouched while the player is typing. Bet and Raise action boxes are orange. A fold loss uses a softer pink result box; other losses remain red. The client plays a low bust-out cue, a 120-millisecond shaker cue for bets and raises (twice above four big blinds and three times above ten), a ding for all-ins, and a celebration cue for the table winner.

A fully automated table replays each reference-player action and community-card reveal using the Automated Player Delay. Between hands it uses the Uninterrupted Dealer Delay, without waiting for the human-facing deal clock.

Both applications read and create the shared INI-style configuration at `~/.config/azonelayer/blindskill/blindskill.conf`, but their Settings dialogs intentionally expose different application-specific controls. The client exposes its player/deal clocks, presentation delays, preferred ports, auto-connect, and sound. The server exposes [chips] Small Blind and Stack amounts, blind-level thresholds, server logging, ports, and action-log column visibility. Small Blind and Stack must be positive multiples of the smallest configured chip denomination; saved changes apply when the next competition starts, while existing competitions retain their values. Delay preferences use editable fractional-second fields without spinner controls, a unit suffix, or trailing zeroes. Updating either presentation delay reschedules its active wait immediately; a new value shorter than elapsed time completes that wait. New Game and Custom Game both collect the human player's explicit Fold-card logging consent; Custom Game remembers its last choices only for the current application run. The client presents each reference-player action for the configured automated-player delay even if the server returned several authoritative actions together. Pausing calls the authoritative server pause endpoint, so paused time does not advance time-based blinds. The server raises the blind level before a new hand after either configured threshold is reached. Do not encode state in color alone; provide text labels and accessible names.

Action history is an expandable accessible panel per seat (and a compact hover summary for pointer users). It contains street, action, and amount. The action composer gives only legal action buttons, a formatted amount field, denomination increment/decrement controls, and concise explanations of the current wager, call amount, and min/max constraints.

Connection UI accepts host and port, then progressively enables competition and table pickers. It displays a copyable connection URL following `https://host:port[/competition[/table[/player]]]`. The later player segment should appear only after the viewer/player identity is attached.

## Server console

The server window has an expandable tree (House → competition → table → player) and an action table ordered Index, Timestamp, Game, Round, Street, Player, Kind, Action, Value, Stack, Gain, Pot, Hand, Hole. Player, Action, and Value are always visible; Index is hidden by default; Hole is never visible; the other columns default to visible and can be changed on the separate Action Log Columns Settings tab without changing order. Timestamp is local sortable `yyyy-MM-dd HH:mm:ss` with one-second precision and no timezone. Game is `Competition:Game`. When a table identity is needed it is `Competition:Game:Table`; `Competition:Game:` means its implicit Hydrogen table, while the version without the trailing colon is the game itself. `Value` records the betting or pot operation; for each `Deal` it is the number of remaining players and Hand says `Heads Up` when that value is two. Signed `Gain` records a player's profit or loss, while `Pot` records the authoritative amount at the turn boundary. Community-card rows use the action `Reveal`; the dealer-button operation remains `Deal`. Showdown losses are logged as `Lost`. A hidden `Hole` column stores reference-player folding cards and API-player folding cards only when that player opted in, while cards shown at showdown are always recorded, for saved CSV/JSON action logs only; it is never shown in the server UI. `Quit Game` is followed immediately by the chip-leader `Table Winner` row, with lower seat winning any chip tie. The File menu contains only `Save Action Log…`; it saves a suggested `HHmm-BluffSkill-action-log` folder containing `actions.csv` and `summary.json`. The backing CSV is also continuously written and flushed after every action to `~/AzoneLayer/BluffSkill/actions.log`; it is truncated at server launch and by `Server → Clear Log`, and the save operation copies it as `actions.csv`. CSV exports include Timestamp and Game in the displayed default order. JSON exports nest games by competition using `competition_name`, use `table_players` for the player list in each top-level player collection, and include a nominal table field plus rounds, duration, winner, runner-up, kinds, and constitution at each game. `Store Actions in JSON`, on by default in Server Settings, controls whether each game also contains its `actions` list. Operational REST activity is not shown in the UI; it is written to `~/AzoneLayer/BluffSkill/server.log`, rotates nightly to `server-YYYYMMDD.log`, and retains seven days for terminal inspection. `Detailed Server Logs`, off by default in Server Settings, adds compact JSON request and response bodies to that local file. Export suggestions begin with the current 24-hour `HHmm-` time. The kind is `API`, `Leo`, `August Leo`, `Virgo`, `August Virgo`, or `Libra` for player rows; game-level rows leave it blank. Each reference-player tree entry explicitly identifies its type (for example, `Leo reference player` or `Virgo reference player`) and expands to that type's server-private operating parameters. It displays its listening address and eventually exposes controlled actions: create competition, add reference players, pause/resume, snapshot, and export OPML.

## Product principles

- Make it obvious whose turn it is and what action is legal.
- Prefer persistent labels to tooltip-only information; supply keyboard paths and screen-reader names.
- Keep poker information dense but staged: table state first, details on demand.
- Treat reconnect and stale state as ordinary: show a quiet reconnect indicator and refresh from event sequence.
